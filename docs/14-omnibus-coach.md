# 14 · 通用费曼学习教练（Omnibus Coach）—— 架构设计
> 适用范围：范围：通用核心 —— 多学科费曼教练总纲（新起点，Phase A–C 见 §4/§5/§6）

> 背景（2026-09 讨论）：从"数学 ITS"升级为**通用学科 AI 对话费曼学习教练**。
> 现状（数学）不推翻：封装为**第一个预置学科**（subject preset）继续运转；
> 新增"通用学科层"，让任意学科可注册、可学习。本文件=总纲；实施分 Phase A/B/C（交 Euler）。

## 0. 已锁定的用户决策（讨论结论）
1. 学科选择自由；**AI 一次生成"知识点单元级"大纲**（细粒度，非章节粗粒度）。
2. 学习体验：**地图为主、对话（费曼）为辅**——按学科切换地图，对话是费曼/答疑入口。
3. 大纲可**随时重新生成**；**已学内容不因换路线丢失**（概念层映射，可自主显式重置）。
4. 学习内容**懒生成**（学到哪条生成哪条），最大化省 token 与可拓展。
5. 冷门学科参考材料：AI 检索出**候选清单 → 用户勾选/上传 → AI 整理为本地引用材料库**；
   **不做整本自动下载**（版权/质量边界）。
6. 现有费曼对话与评估、FSRS、关卡进度等骨架**保留并跨学科复用**。

## 1. 概念分层（通用层）

```
Subject 学科
  └─ Outline 大纲（persist 文件/表；AI 一次生成；用户可审阅/重生成；含依赖序与分组）
       └─ Unit 单元（知识点单元级条目：元数据 + 概念标签集 + 前置 + 建议难度）
            └─ Content 学习单元内容（懒生成：讲解/例题/练习/费曼任务；学科化模板）
Concept Layer 概念标签库（跨大纲、跨学科可移植的掌握证据挂载点）
Progress/Memory（掌握度 + FSRS + 关卡地图视图）——语义复用现有引擎，key 由 node 升级为
             (subject, concept-tag/unit) 双轨
Materials 材料层（候选清单 → 勾选导入 → 本地引用库 → 供讲解/出题引用）
```

- **数学 = 预置学科 preset**：现有 5 学段蓝图/总序/锚点/内容映射为"数学学科的一个 Outline"，
  既有引擎语义（sympy 判题、总序门禁）作为该学科 preset 的评估与规则插件继续生效。
- **数据**：SQLite 增加 subject 命名空间（现有表加 subject 列或按 subject 分文件）；
  大纲文件按 `subject/<outline_id>.yaml` 存放；概念层独立表。

## 2. 关键机制规格（要点，供 Euler 细化）

### 2.1 大纲生成与审阅
- 触发：用户选学科 → AI 起草 Outline（条目=单元：标题/目标≤3/概念标签集/前置猜测/难度/分组）→
  内部校验（依赖无环、标签可归一）→ 地图可预览 → 用户采纳/局部改/丢弃重生成。
- 热门学科可附"锚点目录"（像数学课标）提升质量；冷门学科无锚点，靠审阅+纠错+重生成兜底。
- **R36 起（用户指令）：起草必须能读材料**——
  - `POST /outline/draft` 注入该学科**引用材料**（分节摘要，受字符预算约束，`MF_OUTLINE_MATERIAL_MAX_CHARS`）；
    材料是**可选输入**：无材料 → 退化为仅按 `brief` 起草，不报错；**禁止整本塞进一次调用**；
  - 每个单元带 `materials: [{title, section}]` 溯源（材料的**真实章节名**或**逐字引文**）；
    服务端校验不成立 → **驳回重生成一次**，仍不成立则**剔除该引用并记问题**（宁缺勿造）；
  - 采纳时服务端反查并记录 `source_materials: [material_id…]`（**不由客户端自报**），大纲页显示
    「本大纲依据的材料」。
- **R37 起（用户指令 · 产品级地基变更）：教材＝权威真源（Source-First）**——
  - **真源优先级**：**教材原文 > 用户补充材料 > 大纲 brief > 模型自有知识**（自有知识只可用于解释/
    类比/举例/衔接，**不得引入教材未陈述的事实/数字/结论**）；无教材时退回 AI 起草，并**显式标注
    "本内容无教材依据"**（覆盖账本里可见）；
  - **大纲＝书的目录**：`outline.bookmap` 把材料解析成**章 → 节地图**（PDF 目录 + 运行页码精确对齐；
    Markdown 标题；页块兜底并如实标注识别路径），再由地图派生单元。**每个章/节条目必须映射到 ≥1 个单元**，
    未映射 → **违规**（`PUT /outline` 中文 422）；起草时模型漏标的条目会先**确定性回捞**已有单元、
    再按**教材目录**补齐（内容取自书的目录，非编造）并记问题——**不得悄悄丢章节**；
  - **注入不省成本**：默认**不限**（`MF_MATERIAL_INJECT_MAX_CHARS=0`），按结构注入**完整正文**；
    书太大时按 `MF_MATERIAL_BATCH_CHARS`（默认 60000）在**章/页边界**分批调用（章节地图每批都注入），
    **绝不"前 N 字"截断**；若显式设了上限，它只是**单次调用预算**（`min(预算, 分批阈值)`）——
    **调小预算只改"每次喂多少"，不丢章节**（R38 §3 共存口径；总覆盖面由覆盖账负责），
    单节自身超预算时**整节注入**（宁可不截断）；**任何情况都不得静默丢材料/章节**（R39 铁则）；
  - **单元出稿＝把该教材段落讲全**：注入该单元对应章/节的**完整正文**；讲解是该段的完整演绎
    （可换措辞/举例/类比；不许省略要点、不许加教材外事实）；`taught_facts[].text` 与每道题
    `basis.quote` 必须**逐字出自教材**（闸门**第三类校验**，S5）——找不到 → 先重试一次，
    题目仍不行则**丢弃该题**，事实句仍不行则**整单元失败**（`status="uncovered"`，中文告知
    "教材未覆盖此单元"，**不落盘、不编造**）；
  - **覆盖账本**（S6）：每单元记录 来源材料 + 节标签 + 覆盖状态（完整/部分/未覆盖）；
    `GET /subjects/{sid}/coverage` 给出 `已覆盖节 / 总节` + **未覆盖清单** + 逐单元状态，
    大纲页同源展示；
  - **扫描/图片版 PDF 的诚实边界**（S7）：入库即检测**文本层健康度**（每页字符数/有文字页占比）；
    无文本层或极稀疏 → 中文告知"本书是扫描版、未提取到文字，请先 OCR 或改用文本版"，
    **起草与采纳都拒绝**（不得静默生成"没读到书的大纲"）；**不做 OCR**（本地无引擎），但必须如实报告；
  - **既有机制一律复用**（S9）：引文尺子 `content/citations.py`、闸门结构、材料存储
    （`content/subjects/<sid>/materials/`）、学科生命周期、`attempts/feedback` 表——**不新建平行机制**。 
- **R36 P1–P5（仍在）：由易到难 · 零基础读一本书**——
  ① `prereqs` 无环（既有）**且先修 `difficulty` 不得高于后继**（新校验；`source=="roadmap"` 的
  预设大纲豁免，其顺序由课程蓝图总序 R18 治理）；② **首个单元（`prereqs` 为空）必须完全零基础可学**；
  ③ `group` 表达章/阶段层次，组内先易后难；④ 难度提升**只能靠已教事实的累积**（与 R35 同源，
  当前为 prompt 约束，机器校验待 R35 的 `taught_facts/derivable` 落地）；⑤ 不新增引擎——
  沿用掌握度 + FSRS，"学完一本书"＝沿大纲顺序推进到末单元。

### 2.2 概念层与进度映射（换路线不丢进度的关键）
- 每学完一单元，AI 把内容归一为**概念标签集**，掌握证据挂 tags；
- 大纲重生成后：为新大纲每个单元计算其标签 vs 已掌握标签 → 命中即"等效已掌握"（地图标绿、可跳
  可快速过），未命中照学；用户显式"重置学科进度"= 清概念层（可选）。
- 评审/费曼/FSRS 依据 (subject, tag/unit) 双轨寻址，兼容旧掌握数据迁移。

### 2.3 内容懒生成与预算
- Outline 只存元数据；单元 Content 按需生成（沿用现流水线 + auto/纠错/熔断 + token 限额）。
- 复用现有 guardrails 语义：问题率熔断、auto 重生成替换（学科化 source 标记）。

### 2.4 评估插件（按需启用）
- L1 结构化可验：数学 sympy（已有）；扩展：数值+单位、公式符号；代码类沙箱执行（后置）。
- L2 语义 rubric：史地政文/概念类 → 现有费曼 rubric/evidence/追问机制直接复用（按学科配 rubric
  模板）。
- L3 技能 runner：写作/编程/语言类特殊评测（Phase B 再细化）。
- 铁律不变：能确定性验证不交 LLM；验不了走费曼评估 + evidence。

### 2.5 交互与地图泛化
- 主界面：学科切换 + 该学科大纲地图（单元分组/首领/进度/复习）→ 单元进入学习（讲解→练习→费曼）；
- 对话（费曼口述/答疑/大纲反馈）为第一入口之一的副通道；题目块通用化（选择/填空/计算式/语义问答/
  代码/绘图/口语——先实现数学已有 + 语义问答两类，代码/绘图后置）。

### 2.6 材料层（Phase C 起点）
- AI 检索 → 候选清单（标题/来源/摘要/理由）→ 用户勾选或上传（自有 PDF/文本/链接）→ 本地解析为
  引用库 → 单元生成时作为 ContextBlock 注入来源（可追溯）。
- 版权边界：不自动整本抓取；来源标注；用户自审。

## 3. 取舍与风险（已讨论，默认接受，可复议）
- A 冷门学科无权威课标：大纲可能一般 → 纠错 + 重生成 + 用户审阅兜底（接受）。
- B 评估插件渐进：先 L1(扩展)+L2，L3/代码沙箱后置（接受）。
- C 迁移策略：数学封装为 preset；通用性验证改用"用户自建/自导入学科或临时示例学科"路径
  （§6），验证后再清理数学专属耦合。

## 8. 内容源策略与材料层（决策 2026-09-09）
- 每学科可选**内容来源策略**：AI 全生成 / 本地教材导入 / 联网候选清单 / 混合 —— 用户可随时自选切换；
- 材料边界（沿用候选清单+本地导入口径）：联网搜罗 = AI 检索出候选清单（标题/来源/摘要）→ 用户勾选 →
  本地化引用；本地导入支持用户自有/授权 PDF·文本·目录 → 解析为引用库；**不做整本自动下载**；
- 数学（预置）同样具备这些来源策略能力（不独特）。

### 8.1 Phase C 落地（2026-09-09，C1–C3）
- **联网检索后端 provider 抽象（C1）**：默认未启用（search 返回明确中文提示 + `backend:
  {configured:false}`，UI 标注"未配置检索后端"）；配置 `MF_SEARCH_PROVIDER=searxng` 与
  `MF_SEARXNG_URL`（自托管实例需开启 JSON 输出）后：真实检索 →（配 LLM_API_KEY）LLM 整理候选
  清单（含 reason；输出 url 只取原始结果防杜撰）→ select 勾选抓公开网页正文入库
  （仅 http(s)/text/html，字符上限，失败回落摘要）。robots/版权边界：只抓用户**勾选**的公开
  网页；不整本下载书籍；PDF 二进制 URL 不抓（走 C2 上传）。
- **PDF/文档解析（C2）**：pypdf（BSD-3-Clause，Py3.14 兼容）解析用户上传 PDF → 分页/分节文本
  → 引用库 kind=pdf（保留源文件名；≤20MB/≤400 页/每页字符上限，超限中文报错；扫描图片版提示
  先 OCR 或文本粘贴；粘贴文本入口保留）。
- **学科管理收敛（C3）**：停用学科内容在 仪表盘/关卡地图/图谱/推荐/复习队列按 subject.enabled
  一致隐藏（视觉层，引擎 409 之外）；学科列表 = 管理页（启用 / 已移除(可恢复) 两组：重新启用、
  custom 连同文件删除、math 拒 hard）；soft 移除对 math 亦全量清其内容节点进度（大纲/roadmap
  留盘可恢复）。来源策略/材料/检索/上传/删除均在学科大纲页"学科管理"卡收敛操作。
- 环境：`.env` 增 `MF_SEARCH_PROVIDER` / `MF_SEARXNG_URL` / `MF_SEARCH_TIMEOUT_S` /
  `MF_SEARCH_MAX_ITEMS` / `MF_FETCH_PAGE_MAX_CHARS` / `MF_PDF_MAX_BYTES` 等（见 .env.example）。

### 8.2 材料注入预算用户可控 + 多材料合并（R38，2026-09-10）
> 用户指令："字符也太少了吧——**给我一个滑块，我可以在导入时自己控制**，**同时允许不设上限**"，
> 并补问"我导入**多份**材料也 OK 吧"。
- **两个滑块（每学科独立，落 `subjects.meta_json`）**：
  **单次调用预算**（`MF_MATERIAL_BATCH_CHARS`：省着用 20,000 / 常规（默认）60,000 / 充裕 150,000 /
  **不限 0**）＝"每次喂多少"的**主控**；**总注入上限**（`MF_MATERIAL_INJECT_MAX_CHARS`，默认**不限**）
  ＝**真硬上限**（R42 裁定，见下）；优先级 **单次请求参数 > 学科滑块 > `.env` > 内置**；
  非法值 → 中文 422。
- **两个滑块的承诺不同（R42 · 架构侧 R41 §3-① 裁定）**——**不许混写**：
  - **滑块 A（单次调用预算）**：调小 → **只是分更多批，一个章节都不会少学**
    （`dropped` 恒空、覆盖账不变）；**A3 铁则只管 A**；
  - **滑块 B（总注入上限）**：**是真上限** —— 跨批次累计注入字符，到顶后**在章/节边界停止**，
    剩余章节**整条不注入**（**绝不在句中截断**）；但**每一处未注入都必须有中文账目 +
    覆盖账按材料分组显式列出**（`not_injected` / `uncovered_materials`）。
  - 一句话：**A 管"每次喂多少"，B 管"总共最多喂多少，超了明说哪些没喂"。**
  - 用户设"花费天花板"的**唯一意义就是真的能封顶**——否则该滑块是装饰品，
    用户会以为"我设了上限"而实际没生效（正是铁则要消灭的"未按用户以为的方式使用"）。
  - **B 触发时覆盖账如实降**：因总上限未注入的章节**不计入覆盖**（"没喂给模型"谈不上覆盖），
    并要求每一处都能解释"它去哪了"。**B=0（默认不限）时行为与 R38 逐字一致。**
- **节粒度**：优先 Markdown 标题/目录；PDF 无标题时**按页合并成"章级"单元**（`MF_PAGE_UNIT_CHARS`=8000），
  **页号保留**（`第 N 页`）供溯源；覆盖账按**章级**统计、**页级可下钻**。
- **安全阀（A4）**：按「字符 ≈ token」粗估，将超上下文 → **不发请求**，自动分批 + 中文说明
  "本书较大，已分 N 批处理"；**任何情况不得静默失败**。
- **多材料**：所有材料的章节地图**合并成一份**（每条标来源）；覆盖账**跨全部材料**，
  未覆盖清单**按材料分组**；**任何未纳入的材料/章节都显式列出**（不再"只在 prompt 尾部提一句"）；
  **材料角色**：主教材定顺序与范围、补充材料只补细节与例题，未标注按**导入顺序**并在覆盖账注明。
- **界面**：学科管理卡 → 材料区（两个滑块**各自的承诺**分开写清 + 当前值/来源 + 上一轮注入总量与批次数 +
  逐材料明细 + 未纳入清单）；触发总上限时**就地**显示未纳入章节数 + 可展开清单；覆盖卡按材料分组 +
  页级下钻 + "因总上限未纳入"列。
- **R42 B1（R40 §2-4 收口）· 过短条目不得静默吞掉**：材料条目 < ``MF_MIN_ENTRY_CHARS``（默认 200 字，
  标题/目录类）时——**并入相邻单元**或**标为"跳过"**，两种处理都 `ledger.note` 记**中文原因**；
  覆盖账可解释（`skipped_short` / `merged_short`），**且过短条目不计入"未覆盖缺口"**
  （它不是"该覆盖却没覆盖"，而是"按规则跳过"）。**绝不硬塞伪溯源**：没有单元落在该节上时一律跳过。
- **R42 B2（R40 §2-2 收口）· 难度被抬高必须显性**：R37 的难度单调化会把后段单元**抬高**
  （如"第 2 章判 3 → 其后全 3"）——每一处抬高都 `ledger.note(CAT_GENERATION, …)`
  记中文原因（"难度因先修单调性被抬高：2 → 3"）+ 单元 `meta.difficulty_raised`（**大纲页单元行可见**）。
- **R42 B3 · `count` 语义**：有教材/章节地图时**单元数由书决定**，`count` 只在无书时生效——
  起草面板用中文写清（避免误解为 bug）。
- **R42 B4（R40 §2-3 提升项）· 依据细化到"章内该节"**：`unit_material_pack` 额外给出
  `basis_section` / `basis_quote`（**逐字取自该节**）——来源＝① `bookmap` 目录级 `entry.sections`，
  ② 条目正文里**行首编号节名**（如 `1.1 太阳系的组成`）；只有节名与单元标题/概念标签
  **确定性匹配**时才给，取不到就不给（**不编造**）。覆盖账逐单元显示该节级依据。

### 8.5 内容缺失与丢弃的兜底（R54 §A/§B/§C，2026-09-12 · 用户实测撞到）
> 用户原话：「丢完之后就不管了；我打开一章他直接让我讲，我都没看过他的讲解我讲什么。」

- **前置内容守卫（A）**：进"讲解/练习/费曼"前必须有可用的前置内容——
  进 Feynman 前**讲解必须存在且已展示过**（`flow.explained_seen`：讲解正文正常下发后置位）；
  练习前必须有题；追问前必须有可引用的学生原话（既有 reteach 逻辑）。
  缺 → `/session/start|step` 回 `step="content_missing"`（中文说明 + 一键生成），
  **不下发学习步骤、不下发作答入口**；老会话/内容失效 → **退回可进行阶段 + 中文说明**，不 404/409 卡人。
- **丢弃分级（B）**：丢弃**照丢**（R37 教材锚定不许放松），但丢完必须有出路——
  - **严重 → 该单元内容不可用**：讲解为空 / **声明过事实句却一条不剩** / 没有可用练习
    （正常内容文件不可能 0 题：`NodeDoc` 有"每个节点至少 1 道练习"的校验）→
    **不许进这个单元的学习流程** + 一键重新生成 + 覆盖账如实标注（`usable=false` + 中文原因）；
  - **轻微 → 仍可用**：只丢了部分题/事实句 → 单元照常学，界面**如实提示**"N 道题没采用"。
  - **可操作出路**：账本读取时给每条"可补救"记录派生 `action`（就地一键「重新生成这个单元」）；
    重新生成成功后**追加**一条「已重新生成」记录并把该单元此前的丢弃记录标 `resolved`
    （历史行不改，可追溯；幂等，不重复写）。
- **大纲页可见性（C）**：每个单元显示「有内容 / 还没内容」；点"还没内容"的单元**不进空会话**，
  就地中文提示 + 一键生成；生成后状态立即更新。状态与覆盖账、会话守卫**同一实现**（不许两处口径打架）。

### 8.6 教材体检 + 图示认输 + 抽取修正（R55 §A/§B/§C，2026-09-12）
> 用户原话：「系统读不到图片，却照样出内容/出题——**它没说它读不到图**。」
> 用户真实教材实测：126 页、4,664 行、47 张图（20 页）、私用区乱码 17,607 字（6.47%）。

- **教材体检（A · 导入即说人话）**：四个指标＝认不出字符占比 / 被空格拆开的行占比 /
  公式符号数 / 图片数；给**好 · 一般 · 差**三档 + 一句"所以会怎样"（**只给数字不算体检结论**）。
  - 判档口径：认不出 ≥5% → **差**（讲公式/图的部分不可靠）；≥0.5% 或"拆得厉害的行"≥60%
    （≥20% 亦同）→ **一般**；其余 → **好**；
  - **图片数不参与判档**，只让体检多说一句"有 N 张图读不到"（图多不代表抽得差）；
  - 判档用**原始抽取文本**：即使用户拿了修正后的文本，也如实说"这份 PDF 抽出来有多脏"；
  - R37 的扫描版口径（`healthy`/`note`：几乎没读到文字 → 提示 OCR）**原样保留**，体检不掩盖它。
- **图示不可用要显式认输（B · 本轮最重要）**：正文里指向图/表的段落——
  - **可见认输三处同源**：① 注入给模型的文本里**段前加中文标注**（只加标注、**不删正文**）；
    ② 账本一条中文记录（材料级 + 单元级，`kind=figure_unavailable`）；
    ③ 覆盖账 `by_material` / `units[]` 都有字段，界面两处看得见；
  - **不许当依据**：事实句/题目引文的引文若**只**出现在"引用了图/表的那一句"（＋紧随其后 1 句）里
    → 丢弃并记中文原因（`drop_kind=figure_unavailable`）；
  - **整节靠图**（本章每一段都引用图/表）→ **不出内容**，说明原因是"内容基本都在图里、
    系统读不到图片"（学习入口也说清这条，不再含糊地说"还没有内容"）；覆盖状态记"未覆盖：图示不可用"；
  - **粒度口径（实测决定）**：可见标注＝**段落**级；"不许当依据"＝**句子**级。真实教材一"段"
    常常是整页（页内无空行），段落级当硬边界会误丢 17 条事实句里的 10 条、6 条题目引文里的 4 条；
    改句子级后实测误丢 0 条，同时仍覆盖 36 个含图页块（2.0% 正文）；
  - **误判防护**：孤立"图"字（地图/图书/图解/书名）与参考文献行/网址行**不算**指代。
- **抽取修正（C）**：
  - 私用区字形 → 真标点，**两层**：① **已知码位表**（逐条用真实材料核对：目录点线→删、
    句点/缩写点、人名间隔号、撇号、页眉装饰字形→删）；② **通用兜底**（同一码位连排 ≥3
    ＝排版填充，任何书都适用）。**未知私用区字符原样保留**（不猜、不乱删，体检里计入"认不出"）；
  - 拆字空格合并：汉字之间的空格直接合并；拉丁字母只在"该行孤立单字母 ≥5 且占比 ≥60%
    且非清一色大写"时合并（`S o l a r` 并成 `Solar`，`A B C D E F` 这类选项/缩写**不动**）；
  - **保留原始抽取文本**（`*.raw.txt` 留档）+ 材料注明"已做抽取修正"（不静默改内容），
    供日后核查"是抽取错了，还是模型编了"；
  - **"重新整理文字"入口**：给 R55 之前导入的旧材料补做一次修正，**幂等**（第二次无任何变化），
    不动原始上传文件、不动已生成的内容文件。
- **实测（用户真实教材）**：认不出 17,607（6.47%）→ 0；拆得厉害的行 65.5% → 7.0%；
  档位 差 → 好；私用区 17,607 → 0；`行 星 科 学` → `行星科学`；
  `C o 􀆰,L t d` → `Co.,Ltd`；`伊姆克 􀆰德帕特` → `伊姆克·德帕特`。

### 8.7 模型与 Key 在程序内配置（R56 第 0 步，2026-09-12 · 用户点名）

- **Key 的红线**（与"一切显性"同款纪律）：接口**只回掩码**（前 3 位 + 后 4 位）+ 是否已配置；

### 8.8 图示教材模式的最小通路现状（R56 第 1 步实测，2026-09-12）

- **实测结论（真调用，DeepSeek）**：
  - **文字**：可用（1.3 秒、59 token 拿回结构化 JSON）；
  - **图片**：**可用**——自造样张上的柱状图被正确读成"4 根柱子、第 4 根最高"，
    900×1200 页面 ≈ **1124 输入 token + 267 输出 token**，2.3 秒；
  - **PDF 文件直接发**：**不通**——对方接口的"文件"位置只收**图片**（webp/png/jpeg/gif），
    上传 PDF 被拒（"unsupported file"）；
- **能用图的模型**：只有 `deepseek-flash`（`deepseek-v4-pro` **不支持图像理解**）；
    图片必须放在 **user** 消息里（放 system/assistant 会 400）。
  - **模型裁定（2026-09-12 用户）**：就用 **DeepSeek V4.1 Flash（`deepseek-flash`）**，
    **不用 `deepseek-v4-pro`**；两档模型名都设成它（内置默认 / `.env` / 界面「设置 · 模型」三处一致，
    界面显示"来自：你在这里设的"）。旧名 `deepseek-chat`/`deepseek-reasoner` 实测都被静默转成 flash。
- **因此**："把教材文件直接交给模型"这条路在 DeepSeek 上**只能以图片形态走**——
  要么给页面图片（需要渲染或导出），要么换一个"能收 PDF 文档"的服务商（同一套设置页填地址与模型名即可）。
- **诚实出口已经可用**：模型读不出来时会返回"读不出来 + 中文原因"（实测样张没有可辨认文字时，
  它没有编造正文，而是如实说明），程序原样透出，**不当成"读到了空内容"**。

### 8.9 图示教材模式（全 AI 模式）的定位与边界（R56 · 2026-09-12）
> 用户拍板原话：「这个模式直接让 AI 审 AI，不管是出题、问答、生成、判断、评分，所有的一切直接全部交给大模型，你只负责写提示词。」

- **是什么**：第三条路（路径③）。**只服务"非文本 / 高度依赖图示"的教材**，必须**显式选择**。
  入口＝大纲页材料区的「图片为主的教材（全程交给 AI 判断）」，导入的是**页面图片**。
- **程序只做四件事**：① 流程骨架（讲解→例题→练习→费曼→追问→过关→复习，**状态机照旧**，
  不许让模型决定流程）；② 提示词（本模式 9 个独立调用点，可改可恢复默认）；③ 材料递送（把图片交给模型）；
  ④ 记录与显性（每次调用进 AI 对话审计；账本记读不出来的页/图、诚实出口、失败）。
- **本模式内程序不许做**：❌ sympy 独立验算 ❌ 可答性闸门式机器筛题 ❌ 引文逐字比对
  （没有可检索原文）❌ 用规则改模型给的分。→ 用例用 AST 查 import 把这条锁死。
- **诚实边界（写在导入处，四条）**：
  ① "全程让模型自己出题、自己判、自己评，**我不替你把关**"；
  ② "**判对错是模型的判断，没有独立的第二次核对**——数学题也一样"；
  ③ "读图/公式是长处；但**没法逐字核对引用**，依据只能记到第几页/哪张图"；
  ④ "**成本更高**：每一步都要问模型"。
  并且**明说不比文字教材模式更可靠**。
- **模式隔离**：学科一旦有 `all_ai` 材料，就按本模式走（`materials.subject_mode`）——
  判题/评分只走 `service/mode_ai.py`（本模式分支），**不碰**路径②的判题与可答性机器。
- **今天能做到哪一步（实测口径）**：页面图片 → 逐页读（结构化记录：读到了什么/图里画了什么/
  读不出来的原因）→ 入库并标记本模式 → 一键生成单元内容（模型写讲解 + 出题，题目带"由模型判"标记）
  → 进学习会话（讲解直接给、不重写）→ 提交答案由模型判（判不了就走"我看不出来"的诚实出口）
  → 费曼/追问/补答/答疑同一套提示词。**真实端到端已实测**（1 页样张：读图→讲解→3 题→判题
  合计约 0.011 元）。
  **PDF 文件本身对方接口不收**（只收图片），所以"不渲染 PDF、不要截图"这一条在 DeepSeek 上
  需要另选：加渲染依赖，或换能收 PDF 文档的服务商（同一套设置页换地址与模型名即可）。
- **还没接的**：本模式的一键"大纲起草"（现在用手工采纳大纲；提示词已就绪）、设置页里的
  "读图用的模型"输入框。

### 8.10 PDF → 页图渲染（R57 方案 a：主路）+ 方案 b/c 保持可用

> 用户拍板原话：「**选 a，b 可选（毕竟本来就是随时可换），c 保留。**」

- **方案 a（主路，本批落地）**：图示教材模式导入处**可以直接选 PDF** ——
  用 `pypdfium2`（BSD-3-Clause/Apache-2.0，PDFium 打包在 wheel 里、**无需系统依赖**）＋ `Pillow`
  **按页渲染成图片**，一页一张交给模型读（沿用 `read_page` 的分片口径）。
  - **参数可配**（`MF_PAGE_IMAGE_*`）：目标宽 **1024 px**（实测一页 ≈960–1400 prompt token）、
    格式 jpeg（质量 85）、**DPI 上限 200**、单页字节上限、页数上限沿用 `MF_PDF_MAX_PAGES`；
  - **页号留痕且以程序为准**：模型返回的页号一律被覆盖成"我们发出去的那一页"，
    依据永远能追到"第 N 页"；
  - **不许预渲染整本落盘**：渲染出来的图片**一张都不存**（只发给模型）；上传的 **PDF 进缓存目录**
    （`.runtime/pdf_cache/`，已进 `.gitignore`，按保留期 7 天清理并记账），`content/` 里不出现大图；
  - **按需取页范围**：`POST /materials/{mid}/read-pages {pages:"7-9"}` 只重渲染那几页再读一遍。
- **可选依赖 + 优雅回落**：写在 `backend/pyproject.toml` 的 `[project.optional-dependencies].render`；
  **没装不许崩** —— 导入处给**中文说明 + 两条替代路**，界面黄色横幅如实告知（**不假装支持**）。
- **方案 b（保留）**：设置页本来就能换**服务商 / 服务地址 / 模型名** —— 换成"能直接收 PDF 文档"的
  服务商即可**免渲染**，代码侧无任何硬编码绑定。
- **方案 c（保留）**：用户自己把 PDF 每页导出成图片再上传，这条路径**一个字未改**。
- **实测（真渲染 + 真调用）**：1024×1450 px / 123.9 dpi / JPEG 33–36 KB / **8.8–16.1 ms 每页**
  （126 页外推 ≈1.6 s）；3 页真实调用 prompt=4167 + completion=825 ≈ **0.0075 元（空闲）**
  ⇒ **每页 ≈0.0025 元**，126 页读一遍 ≈0.31 元，每页读 2–3 次 ≈0.6–0.9 元/本。
  （架构侧独立实测：1024 px ≈960 token、200 dpi ≈16 ms/页 —— 量级一致。）

### 8.3 「一切显性」铁则（R39 §1，2026-09-10 · 地基级）
> **程序任何时候"没有按用户以为的方式使用他的输入/产出"，都必须被记录、并可见。**

- **单一入口** `service/ledger.py`：所有"丢弃/截断/跳过/降级/失败/重试"必须经它记账
  （禁各处 `print`、禁"只在 prompt 尾部提一句"、禁拿日志文件当交付）；
- **账本字段**：时间 · 类别 · 对象 · **原因（中文）** · 影响面 · 可否补救；类别＝
  材料吸纳 / 生成与校验 / 模型调用 / 覆盖 / 其它；
- **两处可见**：就地（材料页/大纲页/单元页）+ 总账页（`/ledger`，可按学科/类别筛）；
- **覆盖范围不限于材料**：还包括重试次数、题/事实被丢弃、单元失败、降级启发式、模型超时/报错/
  **日限额拦截**/降档/离线兜底、教材未覆盖、学科停用、内容被纠错替换、复习降级回炉、
  提示词改动、审计写入失败与清理；
- **配套**：审计全文落文件（DB 只存路径+预览+字符数）；**默认记录**（不靠开关决定"要不要留证据"）；
  清理要记账（不静默消失）；审计里不得出现 API Key。

### 8.4 所有提示词可在程序内修改 + AI 对话审计（R39 §2/§3）
- **提示词**：`ai/prompt_templates.py` 注册**全部**调用点（＝`ai.calls.CALLS`，用例锁死相等）；
  设置页「提示词」页可改（左列中文名+用途，右编辑器，**system 与 user 两个字段都可改**——
  R42 C2 放开 user）、显示当前值/是否默认/上次修改时间/**与默认的差异行**；
  **按字段或整条恢复默认** + 全部恢复；**必填占位符与硬约束缺失 → 中文拒存**；
  改动**立即生效**（含大纲起草与单元出稿两条自建 provider 路径）并记入账本；
  存储 `prompt_overrides` 表（新数据建表正当，不塞 `subjects.meta_json`）。
- **审计**：每次调用一条（时间/调用点/档位/模型/渲染后 system·user/原始返回/解析结果/重试/token/
  耗时/**最终结局**）；全文落 `.runtime/ai_trace/`；设置里「开发者 / 调试」开关决定界面入口
  （「AI 对话记录」）：失败与丢弃**置顶红色**、可按学科/调用点/是否失败筛、点开可**全文展开**、
  **不做流式**；长 prompt（>10 万字）接口给全文、界面折叠 + 渲染上限；
  **R42 C3**：审计文件**按保留期自动清理**（`MF_AI_TRACE_KEEP_DAYS`，默认 30 天，启动时执行），
  **清理必须记账**（"已清理哪几条"），**不得静默删**。
- **R42 C1 · 模型"降档"逐次记账**：本该走重推理档（think）却跑了轻档（fast）时，
  **逐次**记 `CAT_MODEL_CALL` 中文原因（① 单次覆盖 `think_deep=false`②`model_mode=light` 关掉触发
  ③smart 下未升级）；判据可判定（`base==think 且 decision==fast`）。**保住底线的 light 不算降档**。
- **R42 D · 记账健壮性**：`ledger.write()` 失败**仍不阻塞主流程**，但打一行 stderr 兜底日志
  （`[ledger] 记账失败: …`）——"记账自己失败"不静默；收集器用 **`contextvars.ContextVar`**
  （并发/嵌套不串账）；既有 `print` 一律归口（标准 logging 或账本），
  **步骤轨迹类日志明确豁免**（属"成功路径"，按 R41 §3-① 口径不进账本）。
