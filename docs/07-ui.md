# 07 · 界面与交互规范
> 适用范围：范围：UI 基线（地图为主通用框架；三类交互为 math-preset，学科化见 docs/14）

> 目标读者：前端实现者。原则：**对初学者友好的"图形化 + 短反馈循环"**，
> 不要做成一堆表单，而是像"和一位有耐心的老师共用一个工作台"。

## 1. 三种交互模式（按题型分配）

用户确认三种都要，由**题目声明的 `interactive` 字段**（04 文档）决定渲染组件：

| 模式 | 适用题型 | 交互形态 | 关键组件 |
|---|---|---|---|
| **a. 答题工作台 workbench** | 数值/表达式/方程（可验证类） | 输入区即输即验：输入 LaTeX 类语法 → 实时渲染预览 → 回车提交 → sympy 判题 → 立即反馈（对/错+方向性 hint）。REPL 感。 | `MathInput`（语法+预览）、`FeedbackLine`、`AttemptHistory`（本次作答记录条） |
| **b. 分步引导 guided** | 应用题、证明、概念题（无法一步验证） | 不要求一次成答；系统把题目切成小步（消元？代入？），每步独立反馈（可部分验证的走 sympy；语义步走 rubric/AI 追问）。 | `StepPanel`（当前步+已过步回看）、`StepAdvance` 按钮、`ScaffoldHint` |
| **c. 图形工具 graph** | 几何、函数直观类 | 可拖动图形（点/线/圆/函数曲线）+ 参数滑动条，先玩再答；答案常为"观察结论"（选填/判断题）或调用 workbench 验证。 | `GraphCanvas`（JSXGraph 封装）、`SliderRack`、`ObservationPrompt` |

分配规则（前端按题目 `interactive: [..]` 取第一个支持的渲染；后端不强制）。

> **Phase B（docs/14 §2.5）题型控件**：ExercisePanel 再按 `mode` 提供基础控件——`single_choice`
> 点选选项、`fill_text` 单行填空、`boolean_judgment` 对/错按钮；数值/表达式/方程沿用 workbench
> MathInput。通用学科生成内容至少混合 ≥2 种题型（不重复题面）。

## 2. 页面结构（MVP 三个页面 + 一个设置）

### 2.1 Dashboard（仪表盘 / 首页）
- 关卡地图（阶段 2，docs/10 §2.1）：按学段→主题组展示关卡；节点圆点颜色=状态，👑=主题首领（boss）；
  组进度与"通关 ✓"；未解锁学段灰显；已通全部内容时显示"下一关生成中…"。
- 知识图谱总览（SVG 力导向或分层图；节点颜色=状态：灰 locked/蓝 available/黄 learning/绿 mastered/橙 reviewing）。
  **R18**：`available`（蓝、可点）即**蓝图总序允许集**（docs/09 R18；图谱手写 prereq 不再单独决定可学性）；
  越级节点一律灰显不可点，直接 POST `/session/start` 也会被 409 拒绝并提示前置。
- 今日复习卡：到期节点列表 + "堆积警示"（逾期超 3 天高亮），一键开始复习。
- 推荐学习卡：当前应学节点（最浅 available），显示其前置完成度。
- 断点清单（捡拾后）：显示"你需要先补：…"。
- 统计条：掌握节点数 / 连续学习天数 / 今日完成。

### 2.2 Session（学习会话页）
- 顶部：节点路径面包屑（如 初中→代数·方程→一元一次方程求解）+ 退出按钮（保留进度）。
- 主区按状态机阶段切换：
  - **讲解**：渲染讲解（KaTeX）+ 底部"我没懂，问老师"输入框（答疑，白名单内）+"明白了，看例题"。
  - **例题**：例题步骤逐步展开（点一步看一步解释，`explain_solution_step`）。
  - **练习**：题型对应 a/b/c 组件；显示进度（连续对 X/3）；答错 2 次后显示"回炉提示"入口。
  - **费曼**：见 2.3，作为模态或专页。
  - **R54 内容不足卡片（`step=content_missing`，R54 §A/§B/§C）**：讲解为空 / 还没生成内容 /
    事实依据全丢 / （防御）没有可用练习 → **不下发任何学习步骤与作答入口**，只显示中文说明
    （缺什么、为什么）+「生成这个单元的内容」按钮（`POST /subjects/{sid}/units/{uid}/content`，
    生成完就地回到学习）+「重新检查」+「回仪表盘」。**绝不允许出现"没看过讲解就被要求开讲"**。
- **前置内容守卫（R54 A）**：进 explore/feynman 前必须"讲解已展示过"（`flow.explained_seen`，
  在讲解正文正常下发后置位）；未展示过（老会话/历史数据）→ **退回讲解**并给中文说明
  （`payload.rewound_zh`），不报错、不把人留在半步；恢复旧会话时若内容已失效同样退回。
- 右侧常驻迷你面板：本节点 core_concepts 卡片、当前掌握度进度。

### 2.3 Feynman（费曼口述界面 · R27 v3 混合制）
- 任务卡（`task_pinned`）：`task_prompt` 醒目显示并**全程钉显**（"本环节任务（一直有效）"）。
- 口述输入：大字多行文本框（MVP 打字；录音为 P2）。
- **实时得分条**（R27）：顶部展示 — ① 各维度**账本分**（历轮最高分，带门槛刻度线的进度条）；
  ② 缺口提示（"还差：科学家怎么研究——说出任意一种观测/探测方法即可"）；③ 综合分/门槛进度条；
  ④ 额度徽标"整体稿（首讲+终验）：n/3 · 补答：n/2"。**答追问后立即刷新，涨分看得见**。
- **双提交入口**（R27）：
  - 有追问时：主按钮「回答追问（补答）」= `feynman_answer`；副按钮「整合后完整重讲（终验）」
    = `feynman_submit`（唯一能过关的提交）；
  - 无追问时：单按钮「提交讲解」= `feynman_submit`。
- 提交后进入"评分中"→ 展示**分维度评分卡**：每维分数 + AI 评语 + **逐字引用的你说过的话**（evidence）；
  引文未通过服务端"本轮文本包含校验"的维度显示"引文未通过校验"+降级原因（R27 evidence 纪律）。
- 补答结果横幅：`gap_filled=true` → "✅ 缺口已补上：<缺口描述>（该维度认定线 0.7）。接着请把整段
  讲解整合重讲一遍"；`false` → "❌ 这次还没答到位：…（缺口保留在账本里——**再交一次完整讲解后，
  会针对该缺口再问**）"（F4 文案：不再说"稍后可再追一次"，实际须先交完整稿换取新追问）。
- 边缘带复评提示（R30 F6）：完整稿综合分落 `[门槛−0.05, 门槛+0.08]` 且本轮非 think → 后端以 think
  复评一次取较高分，事件 `feynman_edge_recheck` 对应横幅"⚖️ 本次接近及格线，已用更认真的档位复核一遍"。
- 未达标 → 显示**定向追问**（一次只问最弱缺口那一点，不再自由发问）；整体稿 ≤3（首讲+≤2 终验）、
  补答 ≤2；额度尽或 3 次整体稿未过 → 回炉重学（回炉后账本/轮次一并清零）。
- **追问纪律（R35 S4）**：追问框顶部先**逐字引用学生刚说过的话**（"你刚才说：「…」"）并指出
  "这句话缺的是：…"（`followup_quote` / `followup_missing`）；学生**无可引用内容**（如只写"我不知道"）
  → 后端返回 `reteach`，前端渲染**「返回讲解补讲」卡片**：中文说明 + 未达标维度清单 + 讲解原文
  （当场可回看），**不显示任何"请思考"的追问**（`verdict=reteach`、`next_action=reteach`）。
- 历史复盘入口：过去的费曼记录（"我当时哪里讲岔了"）；R27 起区分"完整稿"/"补答：缺口已补上/
  未补上"记录（含维度分与引文）。

### 2.3.1 挑战题（R35 S3 · 「挑战一下」）
- **入口**：会话页操作区常驻「🎲 挑战一下」按钮（**永不出现在默认流程**——讲解/例题/练习/费曼
  各阶段的默认渲染里都**没有**挑战题；只有用户主动点击才会出现挑战题卡片）。
- **卡片顶部显式标注**（后端直出 `challenge.notice`，前端原样渲染，不得改写）：
  **"挑战题：需要讲解之外的知识，答不出不影响任何进度"**；另显示 `why_hard_md`（为什么它超出讲解）。
- **单题三态，都要能点、都要无后果**：
  - 「开始作答」= `challenge_begin`（展开作答框，**不产生任何记录**）；
  - 「取消」= `challenge_cancel`（丢掉这题，回到原阶段；**不写任何记录**）；
  - 「明确放弃」= `challenge_abandon`（"我不会/我不感兴趣"；**只记复盘**，同样无后果）。
- 提交后展示判分结果（`feedback_md` + `better_md` 参考思路）与一句固定说明：
  "本次记录只进复盘，不计入掌握/费曼账本/任何额度"。
- **待机时页面不显示任何挑战题进度**（不显示额度/轮次/分数影响；`counts_nothing=true` 是契约位）。

### 2.4 Review（复习页）
- 队列逐卡复习：抽题作答（判题）+ 可选"快速自述"开关 → rating 四键（忘记/困难/良好/轻松）。
- 显示每个节点距下次复习的天数。

### 2.5 学科与大纲管理（docs/14 Phase A–C · UI 现状）
- **学科列表 = 管理页**（/subjects）：「启用中」与「已移除（大纲/内容文件留盘 · 可重新启用）」
  两分组；启用卡片提供"大纲管理"入口、移除（停用）；**custom** 额外"连同文件删除"
  （math 预置仅停用/重启用，不提供 hard——服务端 409 治理 + UI 治理提示）；新建自定义学科
  （label/desc/可选 id）。
- **学科大纲页**（/subjects/:id = OutlinePage）：
  - 大纲起草候选（AI/启发式）→ 采纳（revision+1）/放弃；大纲单元表：状态（已掌握/等效/学习中/
    待学 + 可学）、**教材覆盖徽标（完整/部分/未覆盖）**、概念标签就地编辑、懒生成内容、开始学习、重置进度；
  - **R54 C（内容可见性）**：每个单元一行**「有内容 / 还没内容」徽标**（数据源＝覆盖账
    `units[].has_content/usable/content_reason_zh`，与会话守卫**同一实现**）；
    有丢弃时显示「N 道题没采用」；点「开始学习」而该单元**还没内容** → **不进学习会话**，
    就地给中文说明 +「现在生成」；生成后状态**立即更新**（不必刷新页面）。
  - **R55 A（教材体检）**：材料列表每行显示**体检徽标（好/一般/差）**，hover 给
    **中文"所以会怎样"**（如"有 6.5% 的字认不出来…讲公式和图的部分可能不可靠，建议换更清晰的版本"）；
    体检做过的抽取修正会写明"已做抽取修正（原始文本留了一份备查）"；
    覆盖账的**按材料分组**表再加两列：**「体检」**（档位 + 图片数）与
    **「图示不可用」**（这份材料里引用了图/表的章/节数，hover 列出标签）。
  - **R55 B（图示不可用要看得见）**：单元行对"整节内容都在图里 → 没出内容"的单元显示
    **「图示不可用 · 没出内容」**徽标（与"还没内容"区分开：原因不同、下一步不同），
    hover 给中文原因；学习入口也会直说"这一节的教材内容基本都在图里，系统读不到图片内容"；
    账本里另有材料级与单元级中文记录（就地提示 + 总账页都能看到）。
  - **R55 C（重新整理文字）**：PDF 材料行给**「重新整理文字」**按钮——对 R55 之前导入的旧材料
    补做一次抽取修正（修掉认不出的字与被空格拆开的字）；**可反复点，结果一致**（幂等），
    按钮提示里写明这一点。
  - **R54 B（丢弃的出路）**：就地账目里每条"可补救"记录都带**「重新生成这个单元」**按钮
    （账目 `action` 字段，读取时派生）；该单元重新生成成功后，旧丢弃记录显示**「已解决」**并置灰
    （历史行不改，只追加一条"已重新生成"记录）。
  - **R37 教材覆盖账本卡**（S6）：`已覆盖节 / 总节` + **未覆盖清单**（空则明确显示"未覆盖清单为空"）
    + 可展开的逐单元覆盖状态（来源材料/节标签/命中事实数/丢弃题数）；数据源＝`GET /coverage`（与后端同源）；
  - **学科管理卡**（来源策略与材料收敛入口）：来源策略下拉（ai/import/web/mixed）即时切换；
    联网候选清单（检索词 → 候选勾选 → 本地化入库；检索后端未配置时显示中文提示
    "未配置检索后端…"，可自托管 SearXNG 后经 MF_SEARCH_PROVIDER/MF_SEARXNG_URL 启用）；
    文本粘贴导入；**PDF 上传**（pypdf 分页/分节入库，≤20MB，失败中文提示）；引用材料列表
    （类型徽标 文本/网页/PDF + 删除 + **R37 S7 文本层不合格中文告知**"本书是扫描版…请先 OCR"）；
  - **出稿结果如实展示**：`status=uncovered`（教材未覆盖此单元）与 `failed` 都以中文错误横幅显示
    note，**不谎报"已生成"**（R37 S5/S6）；
  - **R38 材料注入预算面板**（材料区，**每学科独立**）：两个滑块——**单次调用预算**
    （省着用 20,000 / 常规（默认）60,000 / 充裕 150,000 / **不限 0**）与**总注入上限**
    （默认不限）；每条都**必显**"当前值 + 来源"（你设定的（本学科）/.env 配置/默认）；
    并排展示**上一轮实际注入总量与批次数**（"共注入 103,448 字，分 2 批"）+ 逐材料吸纳明细
    （字数/章·节条目数/所在批次/是否注入）+ **未纳入清单**；安全阀生效时显示
    "本书较大，已分 N 批处理（不截断、不漏章节）"；
  - **R42 两个滑块的承诺必须分开写清**（界面不许用一句话糊两个滑块）：
    **① 单次调用预算**："调小 → 只是分更多批，**一个章节都不会少学**"；
    **② 总注入上限**："**是真上限**：超了就真的不再注入，但**每一处没进去的章节都会被明确列出 + 中文原因**"；
    触发总上限时**就地**显示"因总注入上限，本教材有 N 章未纳入：……"（**可展开清单**，按材料分组）+
    "调大上限或设 0（不限）后重新起草即可纳入"；上限**小于单章**时另给
    "为不截断正文，首批仍整章注入"的中文提示；
  - **R38 材料角色**：材料列表每行可选「未标注（按导入顺序）/ 主教材 / 补充材料」——
    主教材定顺序与范围，补充材料只补细节与例题；
  - **R38 多材料覆盖账**：覆盖卡按**材料分组**显示 `已覆盖节 / 总节` + 字数 + 页数，
    未覆盖清单**按材料分组**列出（含每条字数），整份未纳入的材料单独红色提示，
    并注明"顺序依据：角色/导入顺序"；另有**页级下钻**（`page_covered/page_total`）；
  - **R42 覆盖账如实降**：因**总注入上限**未纳入的章节**不计入覆盖**（"没喂给模型"谈不上覆盖）——
    覆盖卡新增"因总上限未纳入"列（逐材料章数）+ 就地未纳入清单（含原因），
    并要求**每一处没进去的都能解释"它去哪了"**；
  - **R42 B1 过短条目**：条目 < 200 字（标题/目录类）**不静默成单元、也不静默丢弃**——
    覆盖卡新增「过短条目（N，已跳过/未成为单元，**不计入未覆盖缺口**）」可展开清单（含字数与中文说明）；
    账本同时有逐条中文原因；单元行显示"并入过短条目 N"（若并入）；
  - **R42 B2 难度抬高可见**：难度因**先修单调性**被抬高时，单元行显示徽标
    「难度被抬高 X→Y」（hover 给出中文原因）+ 账本逐条记录；
  - **R42 B3 `count` 语义说明**：起草面板在**有教材时**写明"「单元数」只在没有教材时生效；
    有教材时单元数由书的章节结构决定"（避免用户以为"我填 20 却出 46"是 bug）；
  - **R42 B4 依据细化到节**：逐单元覆盖状态里显示「📍 依据（章内该节）：1.1 …· 引文：…」
    （只有节名能与单元确定性匹配时才给；取不到不显示——**不编造**）；
  - **R39 一切显性 · 就地提示**：材料区/起草候选/单元出稿结果处就近显示本次账目
    （材料吸纳/生成与校验/模型调用/覆盖/其它），每条含 类别徽标 + 对象 + **中文原因** +
    影响面 + 可否补救，并给"看全部账目 →"入口。
- **总账页**（/ledger，R39 §1）：一处看全部（按学科/类别筛；类别计数做成快捷按钮）；
  铁则要求**界面必须能看见**——不许拿日志文件当交付。
- **设置页 →「提示词」**（/prompts，R39 §2；**R42 C2 扩到 user**）：左侧调用点列表（中文名 + 用途一句话 +
  是否默认），右侧编辑器可切换 **system 模板 / user 模板**（各自标"已改"）；显示
  **当前值 / 是否默认 / 上次修改时间** + **与默认的差异（改了哪几行）**；
  **单条（可按字段）恢复默认** + **全部恢复默认**（恢复前确认）；保存前提示"改动会影响生成结果"；
  删掉必填占位符/硬约束 → **中文报错并拒绝保存**（按字段提示）；模板花括号不合法 → 中文教怎么写。
- **设置页 →「开发者 / 调试」**（R39 §3）：开关打开后侧栏出现 **「AI 对话记录」**（/ai-traces）：
  列表时间倒序、可按学科/调用点/是否失败筛、**失败与丢弃置顶并红色标记**；
  点开一条：**上＝发给 AI 的完整内容（system/user 分区折叠），下＝AI 返回的完整内容**，
  等宽字体、可全文展开，顶部一行摘要（调用点/档位/token/耗时/重试/结局/提示词版本）；
  **不做流式**（加载完再看）；超长（>10 万字）只渲染前 20 万字并提示"完整内容见审计文件"。
  ⚠️ 审计**默认记录**，与本开关无关（开关只决定界面入口是否出现）。
- **停用感知**：SubjectSwitcher 只列启用学科；math 停用时仪表盘顶部中文提示（内容/地图已按停用
  隐藏，往学科列表重启用）；停用学科节点在 图谱/推荐/复习队列/关卡地图 数据层一致隐藏
  （docs/14 §9 · C3）。数据来源＝`GET /dashboard` 的 `preset_subject.enabled`（R36 L1；
  **不得**改用 `/subjects` 反推——该端点默认隐藏已移除学科，会把"停用"误判为"启用"）。

## 2.6 设置页 ·「模型与 Key」（R56 第 0 步 · 用户点名"程序里本来就没有这个入口"）

- **一处填完就能用**：服务商（默认 DeepSeek / 自定义 OpenAI 兼容）、API Key（密码框，留空＝不改）、
  模型名（快 / 深两档——**当前都用 `deepseek-flash`（DeepSeek V4.1 Flash）**，它也是唯一能读图的一档）、
  **读图用的模型（R57：留空＝跟随"快"档，也可单独指定只用于读图的模型）**、
  服务地址、每天最多用多少 token（0 = 不限）；
  动作＝「保存」「测试连接」「清除 Key」；测试结果**就地**显示中文（含耗时）。
- **只回掩码**：已配置时显示 `前3位…后4位`，**永不回显完整 Key**；输入框占位符写"已配置（掩码）——留空表示不改"。
- **"当前值来自哪里"**：每一项后面都写来源（你在这里设的 / .env 配置 / 程序默认）——优先级
  **页面设置 > `.env` > 内置默认**。
- **安全提示写在界面上**："Key 存在这台机器的本地数据里，别把这份数据文件发给别人"；
  另有「只放在内存里（关掉程序就要重填）」勾选项（勾上就不写进本地数据）。
- **没配 Key 时**：顶部黄色横幅给中文指引"还没有配模型 Key，去「设置 · 模型」里填一下"；
  下面「当前生效值（只读）」卡里同样指向上面那块，**不再出现第二处含糊说法**（原先的
  "未配置 API Key → 离线兜底模式"已改掉）。
- 变更会进「记录」页（改了哪几项、中文说明；**不含 Key 明文**）。

## 2.7 图示教材模式（全 AI 模式）的入口与标记（R56 第 3 步）

- **入口**（大纲页 · 材料区）：一块标题为「**图片为主的教材（全程交给 AI 判断）**」的区域——
  选择**页面图片**或**直接选 PDF**（可多选；PDF 用"页范围"框限定，如 `1-20`，留空＝整本；
  一次 ≤60 页）→「导入页面图片 / PDF（全 AI 模式）」；旁边还有**「一键起草大纲（本模式）」**
  （按页面记录排大纲；模型没提到的页会并进最后一个单元，界面上会说明）。
  - **PDF 会自动按页转成图片再交给模型**（一页一张、页号留痕；出图宽/格式/DPI 上限在提示里写明）；
    **页面图片不会存进内容目录**（避免仓库膨胀），只留"读到了什么"；
  - 这台机器**没装渲染组件**时：给黄色横幅说明原因 + 两条替代路（自己把 PDF 每页导出成图片上传 /
    在设置页换成能直接收 PDF 的服务商）——**不假装支持、不静默失败**。
- **导入前先把代价写在看得见的地方**（工单 §2，比功能本身重要）：三条代价（**没有独立的第二次核对** /
  **失败了更不容易发现**（更像"说得很有把握但其实不对"）/ **更贵**（一页约 0.002~0.004 元，
  一本 126 页读完约 0.3~0.6 元））+ 长处（能看图、能读公式版式）+ 明确写着
  **"它不比文字教材模式更可靠——只是读得到图，但没人替你把关"** + "要的是页面图片（PDF 本身不收）"。
- **前置校验**：没配能读图的模型 → 按钮禁用 + 中文指引（"去「设置 · 模型」把快档模型名改成
  `deepseek-flash`"）；接口层同样中文 422 拒绝，**不落库**、不静默降级。
- **模式标记（一直能看出当前是哪个模式）**：材料行显示「图片为主 · 全程 AI · N 页」徽标
  （hover 写明"判对错与评分由模型给出，程序不替你复核"）；区域标题旁显示"当前学科：…"；
  材料列表接口也带 `mode/mode_label_zh`。
- **读不出来的页**：导入结果里会点名列出（"读不出来的页：第 3 页、第 7 页"），并写明
  "已如实标注，不会当成内容用"；记录页也有一条中文账目。
- **按需重读（R58）**：图示教材模式的材料行给一个小输入框「重读第几页（如 3 或 3-5）」+
  「重读这几页」按钮 —— 只把那几页重新读一遍（页号从 1 开始数），**其它页的记录不动**；
  完成后提示"已重新读：第 N 页（共 N 页）"，并如实写明"这一步同样要问模型，也会花钱"。
- **一键重读读不出来的页（R59）**：材料行另有一个按钮「把读不出来的页再读一遍」——
  不用记页号，**只重读标着"读不出来"的那几页**（已经读到内容的页永不重读）。
  完成后提示"把读不出来的页又读了一遍（第 N 页）；这次都读到了"，若仍有读不出来的页会
  如实补一句"还是读不出来：第 M 页"。**这份材料没有读不出来的页时，按钮不会去问模型**
  （不花钱），界面直接说明"这份材料没有读不出来的页，不用重读"，
  按钮 hover 也写明"没有读不出来的页就不会调用模型"。连点两次不会重复读、也不会重复花钱。
- **大书也能只读几页（R60）**：页数上限只管"**这次要读的页数**"——
  一本几百页的书，只要在导入时填了页范围（如 `1-3`），或者只重读其中几页，
  就**不会**因为"整本太厚"被拒；只有"整本一次读"或"一次要读的页数确实超了"才会中文报错，
  报错里给的是**真能走**的做法（缩小页范围 / 分批读）。单页太大的保护照旧。
- **旧标签不挡路（R60）**：极少数旧格式页（标签里没有页号，如"封面"）**跳过并如实列出**
  （"另有 N 页标签里没有页号，已跳过：封面（这几页要自己填页号重读）"），
  记录页也留一条中文账目——**不会**为了一个标签让整份材料重导一遍。
- **学起来是什么样（R56 收尾）**：单元内容由模型写讲解 + 出题（题目带"由模型判"标记，
  选择题会把选项下发、**答案不下发**）；进会话时**讲解就是模型的原文**（不再被重写）；
  提交答案后由模型判对错——**判不了**时界面会看到"这一次没判出来 + 中文原因"，
  并且**不算对也不算错**（进度不动、题不换），记录页同时留一条中文账目。

## 3. 输入与渲染（数学公式走 KaTeX）

- **渲染**：KaTeX（`katex`，markdown-it 数学插件或 rehype-katex）。公式统一 `$$...$$`/`$...$`。
- **输入**：`MathInput` 组件：
  - 接受类 LaTeX 简写 + 常见符号面板（分数、根号、幂、括号、运算符按钮插入）；
  - 实时 `katex.render` 预览（输入不合法时预览区红框提示，不阻塞提交）；
  - 提供"转换为标准形式"的容错：前端不解析数学，原始字符串交给后端，后端 sympy 解析失败时返回 `notation_error` 并提示改法（不判错）。
- **几何图形**：JSXGraph 封装 `GraphCanvas`，props 由后端题目的 `graph_def`（JSON：元素类型/坐标/约束/可拖动点/滑动条参数）驱动，**图形定义属于 content 的一部分**（04 文档补 `graph_def` 字段，MVP 先支持直线/圆/点/函数曲线与滑动条）。
  - 学生拖动/操作的结论通过 `ObservationPrompt` 回填（下拉/填空），或用于 workbench 验证。

## 4. 前端工程约定

- Vite + React + TypeScript；状态用 Zustand（或等价）；路由 React Router。
- `api.ts` 封装后端；`/session/step` 的响应即"渲染指令"，前端组件按 `step` 分发。
- **模型模式三档（R12）**：设置页与会话页头部提供 ⚡快/自动/🧠深度 即时切换（PATCH /profile
  model_mode，smart|light|deep）；费曼评分卡与讲解/答疑标注"本次档位：⚡快/🧠深度"（strategy）；
  单次覆盖 `payload.think_deep` 由后端支持（前端默认不发送，用全局模式）。
- 长文本流式：讲解/答疑首版可非流式（转圈即可），P1 再考虑 SSE 流式以降低成本复杂度。
  **（R12-b 已实现可选 SSE）**：AI 动作走 `POST /session/step?stream=1`（协议见 docs/06 §2.1），
  前端解析 `event: result` 后照常渲染；长文本（讲解/答疑回复/追问）配打字机逐段揭示
  （TypeMd，最终仍以完整 JSON 状态渲染，失败自动回退普通提交）。
- 组件层保持薄，判断逻辑一律走后端（见 06 §2 契约）。
- 中文 UI 文案；术语首次出现给 hover 解释（对初学者友好）。

## 5. UI 红线

- [ ] 界面不得显示任何"参考答案"直出按钮（hint 只给方向；后端已护栏，前端也别做）。
- [ ] 费曼评分必须同时展示证据引文，否则用户无法信任。
- [ ] 图形工具不得因拖动产生与后端无关的状态（结论必须提交后端判读）。
- [ ] 仪表盘数字只来自后端聚合端点，前端不做二次统计。
- [ ] **挑战题（R35 S3）不得出现在默认流程**：默认渲染（讲解/例题/练习/费曼/达标）里不出现挑战题；
  只能由「挑战一下」主动唤起，且卡片必须原样显示后端 `notice` 标注。
- [ ] **挑战题不得渲染任何进度影响**：不显示额度/轮次/掌握影响，不把挑战题结果并入得分条/
  费曼账本/缺口清单（它只进 `/history/challenge` 复盘）。
- [ ] **R39 一切显性**：任何"丢弃/截断/跳过/降级/失败/重试"都必须**在界面上看得见**
  （就地提示 + 总账页），不许只在 prompt 尾部提一句、不许只写日志文件。
- [ ] **R39 审计红线**：AI 对话审计里**不得出现 API Key**；用户作答与教材正文**只在本地可见**
  （不随任何遥测外发）；审计页**不流式**渲染。
- [ ] **R38 滑块语义**：调小「单次调用预算」**不得**让界面出现"少了章节"的观感——
  覆盖账、未覆盖清单必须与调小前一致（只允许"批次数"变化）。
- [ ] **R42 两个滑块的承诺不许混写**：界面必须分别写明"① 单次预算＝调小只分更多批、不丢章节"与
  "② 总注入上限＝真上限、超了明说哪些没喂"；触发总上限时**未纳入清单必须就地可见**。
- [ ] **R42 覆盖账不许"没喂却算覆盖"**：因总注入上限未注入的章节一律不计入覆盖，
  且每一处都能解释"它去哪了"（`not_injected` + 逐条中文原因）。
