# 07 · 界面与交互规范
> 适用范围：范围：UI 基线（地图为主通用框架；三类交互为 math-preset，学科化见 docs/14）

> 目标读者：前端实现者。原则：**对初学者友好的"图形化 + 短反馈循环"**，
> 不要做成一堆表单，而是像"和一位有耐心的老师共用一个工作台"。

## 1. 三种交互模式（按题型分配）

用户确认三种都要，由**题目声明的 `interactive` 字段**（04 文档）决定渲染组件：

| 模式 | 适用题型 | 交互形态 | 关键组件 |
|---|---|---|---|
| **a. 答题工作台 workbench** | 数值/表达式/方程（可验证类） | 输入区即输即验：输入 LaTeX 类语法 → 实时渲染预览 → 回车提交 → sympy 判题 → 立即反馈（对/错+方向性 hint）。REPL 感。 | `MathInput`（语法+预览）、`FeedbackLine`、`AttemptHistory`（本次作答记录条） |
| **b. 分步引导 guided** | 应用题、证明、概念题（无法一步验证） | 不要求一次成答；系统把题目切成小步（消元？代入？），每步独立反馈（可部分验证的走 sympy；语义步走 rubric/AI 追问）。 | `StepPanel`（当前步+已过步回看）、`StepAdvance` 按钮、`ScaffoldHint` |
| **c. 图形工具 graph** | 几何、函数直观类 | 可拖动图形（点/线/圆/函数曲线）+ 参数滑动条，先玩再答；答案常为"观察结论"（选填/判断题）或调用 workbench 验证。 | `GraphCanvas`（JSXGraph 封装）、`SliderRack`、`ObservationPrompt` |

分配规则（前端按题目 `interactive: [..]` 取第一个支持的渲染；后端不强制）。

> **Phase B（docs/14 §2.5）题型控件**：ExercisePanel 再按 `mode` 提供基础控件——`single_choice`
> 点选选项、`fill_text` 单行填空、`boolean_judgment` 对/错按钮；数值/表达式/方程沿用 workbench
> MathInput。通用学科生成内容至少混合 ≥2 种题型（不重复题面）。

## 2. 页面结构（MVP 三个页面 + 一个设置）

### 2.1 Dashboard（仪表盘 / 首页）
- 关卡地图（阶段 2，docs/10 §2.1）：按学段→主题组展示关卡；节点圆点颜色=状态，👑=主题首领（boss）；
  组进度与"通关 ✓"；未解锁学段灰显；已通全部内容时显示"下一关生成中…"。
- 知识图谱总览（SVG 力导向或分层图；节点颜色=状态：灰 locked/蓝 available/黄 learning/绿 mastered/橙 reviewing）。
  **R18**：`available`（蓝、可点）即**蓝图总序允许集**（docs/09 R18；图谱手写 prereq 不再单独决定可学性）；
  越级节点一律灰显不可点，直接 POST `/session/start` 也会被 409 拒绝并提示前置。
- 今日复习卡：到期节点列表 + "堆积警示"（逾期超 3 天高亮），一键开始复习。
- 推荐学习卡：当前应学节点（最浅 available），显示其前置完成度。
- 断点清单（捡拾后）：显示"你需要先补：…"。
- 统计条：掌握节点数 / 连续学习天数 / 今日完成。

### 2.2 Session（学习会话页）
- 顶部：节点路径面包屑（如 初中→代数·方程→一元一次方程求解）+ 退出按钮（保留进度）。
- 主区按状态机阶段切换：
  - **讲解**：渲染讲解（KaTeX）+ 底部"我没懂，问老师"输入框（答疑，白名单内）+"明白了，看例题"。
  - **例题**：例题步骤逐步展开（点一步看一步解释，`explain_solution_step`）。
  - **练习**：题型对应 a/b/c 组件；显示进度（连续对 X/3）；答错 2 次后显示"回炉提示"入口。
  - **费曼**：见 2.3，作为模态或专页。
- 右侧常驻迷你面板：本节点 core_concepts 卡片、当前掌握度进度。

### 2.3 Feynman（费曼口述界面 · R27 v3 混合制）
- 任务卡（`task_pinned`）：`task_prompt` 醒目显示并**全程钉显**（"本环节任务（一直有效）"）。
- 口述输入：大字多行文本框（MVP 打字；录音为 P2）。
- **实时得分条**（R27）：顶部展示 — ① 各维度**账本分**（历轮最高分，带门槛刻度线的进度条）；
  ② 缺口提示（"还差：科学家怎么研究——说出任意一种观测/探测方法即可"）；③ 综合分/门槛进度条；
  ④ 额度徽标"整体稿（首讲+终验）：n/3 · 补答：n/2"。**答追问后立即刷新，涨分看得见**。
- **双提交入口**（R27）：
  - 有追问时：主按钮「回答追问（补答）」= `feynman_answer`；副按钮「整合后完整重讲（终验）」
    = `feynman_submit`（唯一能过关的提交）；
  - 无追问时：单按钮「提交讲解」= `feynman_submit`。
- 提交后进入"评分中"→ 展示**分维度评分卡**：每维分数 + AI 评语 + **逐字引用的你说过的话**（evidence）；
  引文未通过服务端"本轮文本包含校验"的维度显示"引文未通过校验"+降级原因（R27 evidence 纪律）。
- 补答结果横幅：`gap_filled=true` → "✅ 缺口已补上：<缺口描述>（该维度认定线 0.7）。接着请把整段
  讲解整合重讲一遍"；`false` → "❌ 这次还没答到位：…（缺口保留在账本里——**再交一次完整讲解后，
  会针对该缺口再问**）"（F4 文案：不再说"稍后可再追一次"，实际须先交完整稿换取新追问）。
- 边缘带复评提示（R30 F6）：完整稿综合分落 `[门槛−0.05, 门槛+0.08]` 且本轮非 think → 后端以 think
  复评一次取较高分，事件 `feynman_edge_recheck` 对应横幅"⚖️ 本次接近及格线，已用更认真的档位复核一遍"。
- 未达标 → 显示**定向追问**（一次只问最弱缺口那一点，不再自由发问）；整体稿 ≤3（首讲+≤2 终验）、
  补答 ≤2；额度尽或 3 次整体稿未过 → 回炉重学（回炉后账本/轮次一并清零）。
- **追问纪律（R35 S4）**：追问框顶部先**逐字引用学生刚说过的话**（"你刚才说：「…」"）并指出
  "这句话缺的是：…"（`followup_quote` / `followup_missing`）；学生**无可引用内容**（如只写"我不知道"）
  → 后端返回 `reteach`，前端渲染**「返回讲解补讲」卡片**：中文说明 + 未达标维度清单 + 讲解原文
  （当场可回看），**不显示任何"请思考"的追问**（`verdict=reteach`、`next_action=reteach`）。
- 历史复盘入口：过去的费曼记录（"我当时哪里讲岔了"）；R27 起区分"完整稿"/"补答：缺口已补上/
  未补上"记录（含维度分与引文）。

### 2.3.1 挑战题（R35 S3 · 「挑战一下」）
- **入口**：会话页操作区常驻「🎲 挑战一下」按钮（**永不出现在默认流程**——讲解/例题/练习/费曼
  各阶段的默认渲染里都**没有**挑战题；只有用户主动点击才会出现挑战题卡片）。
- **卡片顶部显式标注**（后端直出 `challenge.notice`，前端原样渲染，不得改写）：
  **"挑战题：需要讲解之外的知识，答不出不影响任何进度"**；另显示 `why_hard_md`（为什么它超出讲解）。
- **单题三态，都要能点、都要无后果**：
  - 「开始作答」= `challenge_begin`（展开作答框，**不产生任何记录**）；
  - 「取消」= `challenge_cancel`（丢掉这题，回到原阶段；**不写任何记录**）；
  - 「明确放弃」= `challenge_abandon`（"我不会/我不感兴趣"；**只记复盘**，同样无后果）。
- 提交后展示判分结果（`feedback_md` + `better_md` 参考思路）与一句固定说明：
  "本次记录只进复盘，不计入掌握/费曼账本/任何额度"。
- **待机时页面不显示任何挑战题进度**（不显示额度/轮次/分数影响；`counts_nothing=true` 是契约位）。

### 2.4 Review（复习页）
- 队列逐卡复习：抽题作答（判题）+ 可选"快速自述"开关 → rating 四键（忘记/困难/良好/轻松）。
- 显示每个节点距下次复习的天数。

### 2.5 学科与大纲管理（docs/14 Phase A–C · UI 现状）
- **学科列表 = 管理页**（/subjects）：「启用中」与「已移除（大纲/内容文件留盘 · 可重新启用）」
  两分组；启用卡片提供"大纲管理"入口、移除（停用）；**custom** 额外"连同文件删除"
  （math 预置仅停用/重启用，不提供 hard——服务端 409 治理 + UI 治理提示）；新建自定义学科
  （label/desc/可选 id）。
- **学科大纲页**（/subjects/:id = OutlinePage）：
  - 大纲起草候选（AI/启发式）→ 采纳（revision+1）/放弃；大纲单元表：状态（已掌握/等效/学习中/
    待学 + 可学）、概念标签就地编辑、懒生成内容、开始学习、重置进度；
  - **学科管理卡**（来源策略与材料收敛入口）：来源策略下拉（ai/import/web/mixed）即时切换；
    联网候选清单（检索词 → 候选勾选 → 本地化入库；检索后端未配置时显示中文提示
    "未配置检索后端…"，可自托管 SearXNG 后经 MF_SEARCH_PROVIDER/MF_SEARXNG_URL 启用）；
    文本粘贴导入；**PDF 上传**（pypdf 分页/分节入库，≤20MB，失败中文提示）；引用材料列表
    （类型徽标 文本/网页/PDF + 删除）。
- **停用感知**：SubjectSwitcher 只列启用学科；math 停用时仪表盘顶部中文提示（内容/地图已按停用
  隐藏，往学科列表重启用）；停用学科节点在 图谱/推荐/复习队列/关卡地图 数据层一致隐藏
  （docs/14 §9 · C3）。数据来源＝`GET /dashboard` 的 `preset_subject.enabled`（R36 L1；
  **不得**改用 `/subjects` 反推——该端点默认隐藏已移除学科，会把"停用"误判为"启用"）。

## 3. 输入与渲染（数学公式走 KaTeX）

- **渲染**：KaTeX（`katex`，markdown-it 数学插件或 rehype-katex）。公式统一 `$$...$$`/`$...$`。
- **输入**：`MathInput` 组件：
  - 接受类 LaTeX 简写 + 常见符号面板（分数、根号、幂、括号、运算符按钮插入）；
  - 实时 `katex.render` 预览（输入不合法时预览区红框提示，不阻塞提交）；
  - 提供"转换为标准形式"的容错：前端不解析数学，原始字符串交给后端，后端 sympy 解析失败时返回 `notation_error` 并提示改法（不判错）。
- **几何图形**：JSXGraph 封装 `GraphCanvas`，props 由后端题目的 `graph_def`（JSON：元素类型/坐标/约束/可拖动点/滑动条参数）驱动，**图形定义属于 content 的一部分**（04 文档补 `graph_def` 字段，MVP 先支持直线/圆/点/函数曲线与滑动条）。
  - 学生拖动/操作的结论通过 `ObservationPrompt` 回填（下拉/填空），或用于 workbench 验证。

## 4. 前端工程约定

- Vite + React + TypeScript；状态用 Zustand（或等价）；路由 React Router。
- `api.ts` 封装后端；`/session/step` 的响应即"渲染指令"，前端组件按 `step` 分发。
- **模型模式三档（R12）**：设置页与会话页头部提供 ⚡快/自动/🧠深度 即时切换（PATCH /profile
  model_mode，smart|light|deep）；费曼评分卡与讲解/答疑标注"本次档位：⚡快/🧠深度"（strategy）；
  单次覆盖 `payload.think_deep` 由后端支持（前端默认不发送，用全局模式）。
- 长文本流式：讲解/答疑首版可非流式（转圈即可），P1 再考虑 SSE 流式以降低成本复杂度。
  **（R12-b 已实现可选 SSE）**：AI 动作走 `POST /session/step?stream=1`（协议见 docs/06 §2.1），
  前端解析 `event: result` 后照常渲染；长文本（讲解/答疑回复/追问）配打字机逐段揭示
  （TypeMd，最终仍以完整 JSON 状态渲染，失败自动回退普通提交）。
- 组件层保持薄，判断逻辑一律走后端（见 06 §2 契约）。
- 中文 UI 文案；术语首次出现给 hover 解释（对初学者友好）。

## 5. UI 红线

- [ ] 界面不得显示任何"参考答案"直出按钮（hint 只给方向；后端已护栏，前端也别做）。
- [ ] 费曼评分必须同时展示证据引文，否则用户无法信任。
- [ ] 图形工具不得因拖动产生与后端无关的状态（结论必须提交后端判读）。
- [ ] 仪表盘数字只来自后端聚合端点，前端不做二次统计。
- [ ] **挑战题（R35 S3）不得出现在默认流程**：默认渲染（讲解/例题/练习/费曼/达标）里不出现挑战题；
  只能由「挑战一下」主动唤起，且卡片必须原样显示后端 `notice` 标注。
- [ ] **挑战题不得渲染任何进度影响**：不显示额度/轮次/掌握影响，不把挑战题结果并入得分条/
  费曼账本/缺口清单（它只进 `/history/challenge` 复盘）。
