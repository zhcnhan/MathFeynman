# 10 · 闯关式学习与内容自续（产品愿景的成长型闭环）

> 用户愿景（2026-09 讨论）：单用户从**小学 → 初中 → 高中 → 大学 → AI 进阶**一路
> "关卡式打怪升级"式学完整个数学课程，每课都以费曼方式"讲给 AI 听"，最终融会贯通。
> **硬性要求：内容与关卡必须能自行延续——用户不应在学完当前内容后回找开发者加代码/加内容。**

## 1. 现状差距

已有：知识图谱(DAG) + 掌握度/达标 + FSRS 复习 + 会话闭环 + 判题（docs/01–09 已实现）。
缺口：
1. **关卡化体验层**：图谱裸展示，无"学段→章节→关卡→通关解锁"的闯关结构与进度叙事。
2. **课程蓝图（roadmap）**：不存在。它是机器可读的全课程规划（学段/主题/知识点序列/目标/
   前置猜测/难度），独立于内容文件；没有它，自续就无"目录"可循。
3. **内容自续闭环**：`gen_content` 仍是占位（docs/04 §6 定义了流程，未实现主体）。

## 2. 设计（三层，均与现有引擎兼容）

### 2.1 关卡化体验层（campaign）
- 元数据：在 content 中定义 **stage/topic → 关卡分组**与**阶段首领关卡（boss）**；
  boss = 综合评测节点（混合题 + 费曼综述"把本主题整体讲一遍"），通过 = 学段小结完成、
  解锁下一学段入口并触发一次复习整合。
- 解锁规则 = 现有掌握度/前置逻辑（不新增第二套引擎）；表现层：关卡地图、进度、星级、
  当前关/下一关，通关动画与"下一关生成中…"提示（见 2.3）。
- 关卡 = 呈现与导航层 + boss 节点类型，领域引擎不动或极小幅扩展。

### 2.2 课程蓝图（roadmap）
- 独立文件（如 `content/roadmap/primary.yaml|middle.yaml|…`）：条目极轻
  （id 草案/标题/学段/主题/目标 1–3 句/预计前置/难度/是否需思考模型）。
- 分批构建：小学段先行并人工精核，其后逐段补（欧拉可借生成流水线起草蓝图，架构/用户抽查）。
- 蓝图条目≠内容文件：内容按需从蓝图条目生成（见 2.3）。

### 2.3 内容自续闭环（frontier auto-extension）
- 触发器：当前阶段接近学完（如 mastered≥90% 或可用集将尽 + 用户点"继续下一关"）
  → 按蓝图取下一主题组 → 调用流水线生成。
- 流水线主体（实现 gen_content）：规格化批量出稿 → 自动校验（结构/无环/模板渲染/
  **每题 sympy 验算，broken=0**）→ 入库策略（见 §3）→ 图谱节点解锁 → UI 通知。
- 后台执行 + 每日 token 限额（LLM_MAX_TOKENS_PER_DAY），不阻塞用户当前学习。

## 3. 入库质量策略（北极星制 · docs/12 P4 修订 2026-09-08，替代原"混合制"表述）
- **全学段默认自动入库**（source:auto）：流水线校验（结构/无环/模板渲染/**每题 sympy
  broken=0**）+ 概念白名单把关后即入 stages；内容带"纠错反馈"（标记复核 + auto 节点
  自动重生成替换）。
- **运行时护栏**（`service/guardrails.py`）：掌握度/费曼通过作为内容旁证；
  主题纠错问题率 > 0.3 且问题节点 ≥2 且分母 ≥3 → 该主题后续生成转 `_drafts` 熔断待检，
  pending 清零自动恢复。
- **人工锚点节点精写**（现有 13 节点）作为质量基准与对照；蓝图/高难度主题由用户
  "到段前"滚动精核转正（运行期仍无人审）。

## 4. 验收基线（本愿景的"不再找开发者"判据）
- 用户可从当前进度连续通关至**小学结束**，期间系统自动生成并解锁初中代数第一批，
  全程无需用户回找架构/Euler 加内容或加代码（仅使用纠错反馈按钮）。

## 5. 范围与顺序建议（交 Euler）
1. R11 分支覆盖审计 + R12 模型策略（已在 docs/09 裁决，先行收尾）；
2. R12-b 流式输出；
3. **关卡化体验层 + boss 节点**；
4. **课程蓝图（小学段先行）**；
5. **内容自续闭环（gen_content 真实实现 + 触发 + 入库策略 + 纠错闭环）**；
6. 用闭环自动跑出小学段内容（逐步），用户边学边反馈。
（3–6 属大工程，宜分轮汇报；本文件即该愿景的总纲与验收锚。）
