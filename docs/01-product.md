# 01 · 产品愿景与需求
> 适用范围：范围：数学域产品起源（三框架需求）。通用化愿景见 docs/14 —— 本篇是 math-preset 的历史起点，勿当作全产品需求

## 1. 背景与动机

用户初中辍学，现在及未来希望：

1. **捡拾**：复习此前学过但已遗忘的数学知识（小学→初中）；
2. **学习**：按教育体系顺序学完小学到大学阶段的全部标准数学内容；
3. **AI 进阶**：在此基础上拓展到服务于 AI、大模型训练、量化交易的数学内容。

用户期待本系统像一位老师：手把手教学；按当前阶段用费曼学习法出题练习；
评估掌握程度；并依据复习原则在合适时机敦促复习。

## 2. 产品定义

**MathFeynman = 以费曼学习法为核心教学法的本地单机 AI 数学导师（ITS）。**

核心价值主张：用户不是"看视频 + 做题"，而是被系统逼着"把学过的东西讲清楚"——
因为只有能用自己的话讲明白，才叫真正学会（费曼技巧）。

## 3. 需求清单（按优先级分组）

### P0 · MVP（详见 docs/08-mvp.md）
- 知识图谱：节点(知识点)+依赖边，驱动"可学/锁定"状态与路径建议。
- 单知识点教学闭环：讲解 → 例题 → 练习 → 费曼口述 → 评估 → 掌握标记。
- 确定性自动判题（sympy），支持表达式等价判断、数值容差。
- FSRS 间隔复习：产生复习队列，每日提示。
- 本地仪表盘：图谱进度、今日复习、当前推荐节点。
- 内容库：真实中学内容起步（10–20 个节点），全部为**参数化模板题目**。

### P1 · 核心增强
- 三框架落地：捡拾=诊断测试定位断点；学习=主路径；AI 进阶=子图谱（线性代数/概率统计/优化/信息论 → ML 与量化专题）。
- 用户画像：错误类型画像、偏好风格 → 影响讲解风格与出题难度（mastery-based 自适应）。
- 交互模式按题型分配：答题工作台 / 分步引导 / 几何图形工具（见 docs/07-ui.md）。
- 内容生产流水线：AI 按模板生成初稿 → sympy 自动验算 → 人工审核 gate → 入库。

### P2 · 远期（预留扩展位，不在近期实现）
- 多用户与账号（公众化）、云端同步、移动端。
- 语音费曼口述（本地 whisper）、手写识别（明确不做，除非需求变化）。
- 高级学习分析（BKT/DKT 级掌握度追踪——需数据积累后再说）。

## 4. 目标用户与使用边界

- 当前：仅用户本人，单机、本地数据。
- 未来：若验证有效，面向公众（届时新增认证与后端，**引擎与内容库不变**）。
- 内容受众：从小学水平起步的非传统学习者，界面须对"图形化、少术语压力"友好。

## 5. 非目标（本期明确不做）

- ❌ 模型微调 / 自训练模型。个性化一律走系统层记忆。
- ❌ 手写/拍照公式识别（用户已确认不需要）。
- ❌ 账号系统、云端、多设备同步（本地单机；仅在架构上预留 userId 字段）。
- ❌ 移动端 App / 桌面安装包（本地浏览器 + 一键启动脚本即可）。
- ❌ 完整内容量一次性铺开（小学到大学数千节点不可能短期人工编写；靠流水线渐进生成，人工审核每一份入库内容）。
- ❌ 生产级安全/合规（本地单机无此需求）。

## 6. 成功标准（如何知道 MVP 有用）

1. 用户能独立走完 ≥5 个连续知识点的闭环并保持复习队列非空。
2. 用户自评：费曼口述环节确实暴露了"以为会了其实没会"的点（这是本产品区别于题库软件的关键体验）。
3. sympy 判题覆盖 ≥90% 的练习作答（零 AI 判对错）。
4. 一次本地启动脚本即可运行全部功能，无外部服务依赖（LLM API 除外）。
