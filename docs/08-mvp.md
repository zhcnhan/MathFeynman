# 08 · MVP 范围、里程碑与验收

> 目标：用最小可玩版本验证"费曼教学闭环"是否真的有效（用户已选定此为第一验证点），
> 同时把架构骨架（图谱/判题/复习/会话状态机）一次搭对，避免返工。

## 1. MVP 范围（做/不做）

**做**
1. 本地一键启动（backend + frontend），SQLite 落库。
2. 知识图谱最小可运行：加载 content、DAG 校验、节点状态机、推荐。
3. 单知识点教学闭环状态机：讲解 → 例题 → 练习(自动判题) → 费曼(评分+追问) → 达标 → FSRS 排程。
4. 确定性判题：sympy 覆盖 `equation_solution / symbolic_equivalence / numeric_value / boolean_judgment` 四模式。
5. 三种交互模式的最小实现：workbench（必做）、guided（一题演示即可）、graph（几何题 1–2 题演示）。
6. Dashboard + Review 页；Feynman 复盘入口。
7. 内容库首批 **10–20 个真实节点（人工精写）** + `content validate` 工具。
8. 画像记录（错误类型入库；风格偏好初版仅记录+手动调整）。
9. 用户画像→讲解风格的注入（读画像，注入 context block）——初版即可用。

**不做（MVP 明确排除，防止范围膨胀）**
- ❌ 诊断/捡拾全流程（先手工给用户选起点；诊断算法放 M4 后）
- ❌ AI 变体出题（`generate_practice_variant` 调用点保留接口但不启用，MVP 只用模板题）
- ❌ 语音、手写、流式输出、多用户
- ❌ AI 进阶子树内容（图谱结构预留，无内容）
- ❌ 内容生产流水线（先手工精写，流水线 P1）

## 2. 里程碑

| 里程碑 | 交付物 | 完成判据 |
|---|---|---|
| **M0 骨架** | 目录结构、pyproject/package、一键启动脚本、DB 建表、`content validate` 空跑 | `scripts/dev.ps1` 起后端+前端，浏览器打开空 Dashboard 无错 |
| **M1 确定性核心** | domain：图谱/掌握度/FSRS；判题器（sympy 全模式）；单测 | `pytest` 绿：判题用例 ≥ 30 条（含边界/容差/等价），图谱环检测用例 |
| **M2 会话状态机 + API** | service 层闭环状态机 + 06 文档全部 P0 端点 + 会话持久化 | 用 httpx/curl 走通"讲解→答对 3 题→费曼通过→mastered"全链路（无 LLM 时可用桩数据） |
| **M3 AI 接入** | provider/调用点 1、2、4、6、7、8 + pydantic 校验 + 失败降级 + ai_logs | 真实调用 DeepSeek：费曼评分输出含逐字 evidence；故意给坏 JSON 验证重试降级 |
| **M4 前端闭环** | Dashboard/Session/Feynman/Review 页 + workbench + guided + graph 演示 | 真人用户（你自己）完整学 1 个节点，UI 全流程可用 |
| **M5 首批内容 + 打磨** | 10–20 个人工精写节点；体检与文案打磨；复习跨日模拟测试 | 用户连续 3 天使用，复习队列运转正常；费曼体验自评有效（见 01 §6） |

## 3. 验收清单（M5 完成时逐项勾选）

**功能**
- [ ] 一键启动脚本可用；数据在 SQLite 本地文件。
- [ ] 图谱加载 20 节点无环；locked/available 状态正确联动前置。
- [ ] 单节点闭环全流程可走通，中途退出可恢复。
- [ ] sympy 判题覆盖 ≥ 90% 练习作答（剩余为 manual_review 队列）。
- [ ] 费曼环节：评分卡显示分维分数 + 证据引文 + Socratic 追问 ≥1 轮。
- [ ] 达标后进入复习队列；复习 rating 生效；again×2 触发降级回炉。
- [ ] Dashboard 显示：推荐节点、复习队列、断点清单、掌握统计。
- [ ] 练习错答 hint 不含完整解答（自动检查用例覆盖）。

**质量**
- [ ] domain 单元测试覆盖图谱/掌握度/FSRS/判题；CI 或 pre-commit 跑 `pytest + content validate`。
- [ ] ai 层所有输出经 pydantic 校验；断网/坏 JSON 时系统降级不崩溃、状态不脏。
- [ ] 无任何 LLM 直接判题路径（代码审查红线，见 05 §7）。

**内容**
- [ ] 首批节点每份都有 >1 个真实作答样例人工验证过（git 历史可查）。
- [ ] 每个节点都有费曼任务与 rubric；模板题生成后 sympy 验算通过率 100%（broken 模板为 0）。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 费曼评分不靠谱（瞎打分/无证据） | 强制 evidence 引文 + rubric 权重 + 用户可标记"评分不合理"回流人工复核（MVP 留个按钮即可） |
| sympy 解析用户自由输入太脆弱 | 输入容错 + `notation_error` 友好提示；复杂输入引导用 guided 模式逐步化 |
| LLM 讲解幻觉 | 白名单 + 讲解稿注入 + UI 超纲气泡护栏（05 §7）；首批人工精写内容做锚点对照 |
| FSRS 库不可用 | 封装接口，自实现 FSRS-4.5 核心 + 抽查单测 |
| 上下文/范围膨胀 | 本文件即范围；新需求一律先改文档再排期 |
| 内容制作耗时 | MVP 只 10–20 节点人工精写；广度问题 P1 用流水线解决 |

## 5. 开工顺序建议（给实现者的第一个任务序列）

1. 按 02 §3 建目录骨架 + `pyproject.toml`/`package.json` 最小依赖 + 一键启动脚本（M0）。
2. 写 domain 四个模块 + 判题器 + 全套单测（M1，无 LLM 依赖，可先行）。
3. 用 **mock LLM**（本地桩返回合法/非法 JSON）先行开发 service 状态机与 API（M2），再接真模型（M3）。
4. 前端按 07 规范实现（M4），与后端契约以 06 §2 为准。
5. 内容精写与体验打磨（M5）。
